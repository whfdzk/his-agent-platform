## Milvus 启动故障排查与重建

- 症状：`channel is not assigned to any server / CHANNEL_META_STATE_UNINITIALIZED` 刷屏，his-milvus Exited(0)。
- 真因：RustFS 对象存储拒绝写入 `a-bucket`（`Storage resources are insufficient for the write operation`，Milvus 官方认定=对象存储数据损坏/不一致）→ StreamingNode/DataCoord 起不来 → channel 无处分配。非磁盘满（宿主剩 150G、VM 剩 48G）。
- 环境混乱点：compose 文件从 doc/ 挪到根下 docker/，旧容器挂载指向 doc/docker/*（部分路径在宿主机不存在，数据躺在 Docker VM 里）；根下 docker/ 还有一套 10-13 的旧数据；compose 内 `./docker/xxx` 相对路径解析成 `../../his-agent-platform-docker` 是错乱根源。
- 处理：停删 milvus/etcd/rustfs/attu 容器（不动 postgres/redis/neo4j）；旧数据全部备份到 `doc/docker_backup_2026-10-21/`（mv 对 docker/ 下部分目录报 Operation not permitted，改用 cp+rm）；修正 `../../his-agent-platform-docker` 全部挂载路径为 `./xxx`、attu 改用 `MILVUS_URL: milvus:19530` 并加入 tiangong-net。
- 结果：Milvus v2.6.13 全组件 ready（datanode/mixcoord/proxy/querynode/streamingnode），healthz=OK，日志 0 报错。
- 遗留风险（已提醒用户）：正在跑的 postgres/redis/neo4j 仍挂旧路径（doc/docker/...，数据在 Docker VM 内）；若日后从 docker/ compose 全量 `up -d` 会用根下旧数据目录重建这三个库，需先做数据迁移，否则 medical_db 数据不衔接。
