## 对象存储：MinIO → RustFS 改造
- 背景：RustFS 不提供第一方 Python SDK，官方文档推荐用 **boto3**（S3 兼容）接入，必须 path-style + s3v4 签名。
- 变更：
  - 新增 `src/infra/rustfs_client.py`（boto3 S3 客户端，含 `_build_endpoint_url()` 把 `host:port` 归一化为 `http(s)://host:port`）。
  - 删除 `src/infra/minio_client.py`。
  - `src/core/config.py`：`MINIO_*` → `RUSTFS_*`，新增 `RUSTFS_REGION="us-east-1"`。
  - `../../src/main.py`：导入与 `/health/deps` 的 `minio` 依赖项改为 `rustfs`（用 `head_bucket` 探测）。
  - `requirements.txt`：`minio==7.2.18` → `boto3/botocore==1.43.112`、`s3transfer==0.19.2`、`jmespath==1.1.0`（文件是 UTF-16 LE + CRLF，改动需用脚本处理）。
  - `.env` / `.env.example`：同步 `MINIO_*` → `RUSTFS_*`。
  - `../../his-agent-platform-docker`：仅改注释；Milvus 的 `MINIO_ADDRESS/MINIO_ACCESS_KEY_ID/MINIO_SECRET_ACCESS_KEY` 是 Milvus 自身规定的变量名， **不能改**。
- 遗留阻塞：`.env` 中存在未声明的额外键 `deepseek_model`，pydantic-settings 默认 `extra=forbid` 会导致 `Settings()` 直接抛 ValidationError，应用起不来。需改名为 `CHAT_MODEL` 或在 config 里设置 `extra="ignore"`。

## 启动报错修复（DEEPSEEK_MODEL / .env 路径）
- 报错根因：`.env` 有 `DEEPSEEK_MODEL=deepseek-chat`，但 `Settings` 未声明该字段，pydantic-settings 默认 `extra=forbid` → ValidationError。
- 修复：`src/core/config.py` 补声明 `DEEPSEEK_MODEL: str = "deepseek-chat"`（保留用户本意，未改 .env）。
- 同时把 `model_config["env_file"]` 从相对路径 `".env"` 改为绝对路径 `BASE_DIR / ".env"`（`BASE_DIR = Path(__file__).resolve().parents[2]` = 项目根）。原因：`main.py` 已被移动到 `src/main.py`，相对路径的 env_file 依赖启动时的工作目录，换目录就会静默读不到配置。
- `.env.example`：修正 `# MinIO` 注释为 RustFS，凭据 `minioadmin` → `rustfsadmin`，补 `RUSTFS_REGION`。
- 项目结构变更（用户操作）：根目录 `main.py` 已移动到 `src/main.py`，因此启动命令为 `uvicorn src.main:app`，且必须在项目根目录下运行。
- 验证：用 `/opt/miniconda3/envs/his-agent-platform/bin/python` 实测 —— 配置加载 OK、`src.main:app` 导入 OK、uvicorn 启动 OK、换 cwd 到 /tmp 仍能读到 .env。
- 环境坑：本机设置了全局 `HTTP_PROXY/HTTPS_PROXY`（无 NO_PROXY），boto3/botocore **不特殊豁免 localhost**，请求 `http://localhost:9000` 会被代理拦截返回 502。需要 `NO_PROXY=localhost,127.0.0.1` 或给客户端设 `proxies={}`。
