# 2026-10-24 前端适配改造总结

> 配合后端生产化改造（JWT 鉴权、消息幂等、SSE 重连、错误规范化），前端同步修改以下文件：
> - `front/shared/src/types/index.ts` — 请求/事件类型
> - `front/shared/src/api/client.ts` — 统一 fetch 封装
> - `front/shared/src/sse/streamChat.ts` — SSE 流式解析
> - `front/patient/src/hooks/useChatStream.ts` — 聊天主 Hook

---

## 一、JWT 鉴权（可选登录）

- `ChatRequest` **移除 `user_id` 字段**——后端一律从 `Authorization: Bearer <token>` 的 JWT `sub` 中取，不再信任请求体自报。
- `shared/api/client.ts`：统一 fetch 封装自动注入 `Authorization` 头（token 取自 localStorage `his_token`）；收到 **401** 时清除本地登录态并跳转登录页。
- `shared/sse/streamChat.ts`：`token` 为**可选**参数——不带 token 即游客模式（可正常聊天，对话不落库），带 token 才同步历史。token 失效时后端仍返回 401，前端提示重新登录。
- **影响**：聊天不再强制登录；但"历史会话/我的预约"等账号能力仍需登录。

## 二、消息幂等

- 发送消息时为每条用户消息生成 `client_message_id`（`crypto.randomUUID()`）。
- **网络失败自动重试时复用同一 `client_message_id`**，后端凭 Redis SETNX 幂等键识别重复提交，直接重放上次回复，不会重跑 LLM（也就不会重复扣费/生成重复预约）。
- 手动"重新发送"按钮同样复用原消息的 `client_message_id`。

## 三、SSE 流解析增强（`streamChat.ts`）

- 解析器新增对 **`id:` 行**的支持：每收到业务事件记录其 `seq` 游标（保存在流状态与 localStorage，key 按会话隔离）。
- 事件协议扩展：error 事件新增 `retryable` 标记与规范化 `code`：
  ```ts
  { type: 'error'; code: number; message: string; retryable: boolean }
  ```
  `retryable=true`（超时/限流/网关抖动）才允许自动重试；`false`（如 409 会话占用中）只提示不重试。
- 心跳注释帧（`: ping`）被解析器天然忽略，无额外处理。

## 四、断线重连（`useChatStream.ts`）

- 流式请求异常中断（非用户主动 Abort）时，**指数退避自动重试**：1s → 2s → 4s，最多 3 次，每次复用原 `client_message_id`。
- 重连前先调用 `GET /api/v1/chat/stream/pending?session_id=xxx&after_seq=游标` 增量拉取断线期间后端已产出但未送达的消息，按 `seq` 去重后补渲染，再继续新流。
- 收到 `id: seq` 后更新本地游标；done 事件后清空该会话重试状态。
- 429/503 限流响应：读取 `Retry-After` 头，按提示延时后重试并展示"请求过于频繁"提示。

## 五、UI 层细节

- bot 消息错误态展示规范化：显示 `message` 字段（后端已中文化），不再渲染原始堆栈。
- 会话占用中（409）：提示"上一条消息仍在处理中"并禁用发送框直至收到 done/error。

## 六、游客（未登录）模式

- 可以正常聊天（不拦输入框），但**不能新增会话**：
  - `store/session.tsx` 的 `newSession()` 增加 `if (!token) return` 兜底；
  - `ChatPage` 顶栏"新会话"按钮未登录时只弹提示"请先登录后再开启新会话"。
- 不留历史：`ChatPage` 的历史拉取与本地会话登记（`recordSession`）都加了 `user` 判断，游客不发 `/sessions` 请求、不写本地会话索引。
- 顶栏副标题：登录显示"描述症状，帮你分诊挂号"，游客显示"未登录 · 本次对话不会被保存"。
- 挂号成功后的"查看我的预约"入口仅登录用户展示（游客预约不落库）。

## 回归验证清单（上线前）

1. 登录 → 聊天全流程（token 正确注入，`user_id` 不再出现在请求体）；
2. 游客（清空 localStorage token）→ 能正常聊天、能收到流式回复；点"新会话"被拦截；
3. 登录后问"我是谁"→ 后端走长期记忆 → 数据库档案兜底，前端展示姓名/过敏史等；
4. 断网重连：杀进程后恢复网络，观察 pending 拉取 + 退避重试日志，确认无消息丢失/重复；
5. 双开同会话发消息，确认 409 提示；
6. 连续快速发送验证 429 限流提示。
