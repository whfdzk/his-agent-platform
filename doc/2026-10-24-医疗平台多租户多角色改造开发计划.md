| 决策点 | 结论 |

## 1. 现状差距总览

现有技术栈（已核实）：

- **后端**：FastAPI + LangGraph（Supervisor ReAct + Inquiry 9 节点状态机）
- **存储**：PostgreSQL（16 表，asyncpg）+ Redis（业务 KV + AsyncRedisSaver checkpointer）+ Milvus×2（文档检索 / 长期记忆）+ Neo4j（知识图谱）+ RustFS（S3 兼容对象存储）
- **可观测**：Prometheus + Sentry + loguru + request_id
- **部署**：Docker Compose + Nginx（SSE 调优）+ 多阶段构建
- **前端**：pnpm monorepo（patient / admin），React 18 + TypeScript + Vite

| # | 需求能力 | 现状 | 差距等级 |
|---|---|---|---|
| 1 | 统一身份 + RBAC + 多租户隔离 | JWT 仅 `sub=patient_id`，无 role/scope/tenant；管理端前后端均无鉴权；存在 IDOR | **P0 阻断** |
| 2 | 安全分诊 + 急症分级落库 | 急症靠关键词+LLM 软判断，不落库不分级 | **P0 阻断** |
| 3 | 高危动作「草稿+确认」闭环 | 医嘱/处方/转诊无；挂号 mock 直接 `confirmed`；诊断直接落库 | **P0 阻断** |
| 4 | RAG 接线 + 分层检索 + citation + 拒答升级 | 整套 RAG 是死代码；worker 纯 LLM；幻觉检测 fail-open | **P0 高** |
| 5 | 审计/日志脱敏/PHI 留存治理 | 审计只写 loguru；`chat_messages.content` 明文落库 | **P0 高** |
| 6 | 人工接管（human-in-the-loop） | 无队列 / 无 interrupt / 无坐席台 | **P1 高** |
| 7 | 医护端（摘要/分诊/初稿/可审查辅助） | 无医护端接口与页面 | **P1 高** |
| 8 | FHIR 抽象 + Mock 适配器 | 无 | **P1 中** |
| 9 | 评测体系（gold set / Recall@5 / 盲评） | 无 | **P1 中** |
| 10 | 可观测（histogram / SLO / 告警 / 审计落库） | 仅 2 个 Gauge；无 SLO；无告警 | **P1 中** |
| 11 | 运营管理端 + 版本回滚 + 模型热更新 | 管理端仅 4 页；配置需重启；文档无版本 | **P2 中** |
| 12 | 隐私（删除权/撤回授权/被遗忘） | 无删除/撤回；脱敏仅 auth/profile 两处 | **P2 中** |

## 2. 分阶段路线图

## 3. 关键架构设计

### 3.1 四平面落地映射

| 平面 | 落地位置 |
|---|---|
| 数据平面 | 病历（consultations/patients）、文档（documents + document_versions + RustFS + Milvus）、会话（conversations/chat_messages）、工具执行结果（tool_executions）、检索索引（Milvus×2 + Neo4j，均加 tenant） |
| 控制平面 | 身份权限（identity）、临床策略（triage.py）、意图路由（supervisor 规则前置 + LLM 兜底）、模型路由（model_configs 热更新）、人工确认规则（clinical 状态机 + handoff） |
| 执行平面 | 确定性工作流（inquiry/graph.py）、RAG（doc_rag/graph_rag/nl2sql/prescription_review 接线）、模型调用（get_llm）、FHIR 工具（Mock Adapter） |
| 治理平面 | 审计（audit_logs）、评测（evaluation）、隐私（privacy）、安全（RLS/密钥/脱敏）、成本（token_usage）、延迟（Histogram）、事故响应（SLO/告警） |

**编排原则**：模型只负责理解与生成；权限校验、状态转换、数据访问过滤、高风险动作确认全部由后端策略决定，禁止 worker agent 直接落库或下医嘱。

### 3.2 身份 / 多租户数据模型

```
tenants 1─N orgs 1─N users
tenants 1─N patients / clinicians（业务档案）
users N─N roles N─N permissions
users 1─1 patients（patient user）/ clinicians（clinician user）
```

**tenant_id 注入（三层纵深）**：

1. **应用层**（主路径）：`AuthContext.tenant_id` 写入 `contextvar`；`BaseRepository` 与所有查询自动 `WHERE tenant_id = ?`。
2. **RLS**（纵深）：PG `ENABLE ROW LEVEL SECURITY` + policy，配合 `SET LOCAL app.tenant_id`；P0 先应用层过滤，P1 再启 RLS 兜底。
3. **存储层**：Milvus 文档与长期记忆、Neo4j 节点、Redis key 全带 tenant 维度。

### 3.3 人工接管队列 + interrupt

```
高危节点 ─interrupt()→ HandoffTicket 落 PG + checkpointer
坐席认领 → 查看上下文（会话 + 状态 + 脱敏档案）→ 回复 / 确认草稿
Command(resume={"decision": ...}) → 图恢复执行 → 落库(confirm) → SSE 推送
```

`HandoffTicket` 字段：`id / tenant_id / patient_id / session_id / thread_id / reason / status(open/claimed/resolved/expired) / priority / assignee_id / payload`。

### 3.4 高危操作状态机

```
DRAFT → PENDING_CONFIRM → APPROVED / REJECTED / EXPIRED
对象：order（医嘱）、prescription（处方）、referral（转诊）、diagnosis（诊断）、appointment（挂号）
```

规则：模型/Agent 只能产出 DRAFT；APPROVE 需 `role=clinician/admin` 且 scope 覆盖对应科室/租户；记录 who 生成 / who 确认 / 证据来源 / 置信度 / 时间。

### 3.5 FHIR Adapter

```python
class IFhirAdapter(ABC):
    async def get_patient(self, patient_id) -> FHIRPatient: ...
    async def create_referral(self, referral) -> str: ...
    async def create_medication_request(self, order) -> str: ...

class MockFhirAdapter(IFhirAdapter): ...  # 内存 / PG 存储，先打通流程
```

### 3.6 RAG 接线 + 分层检索 + citation + 拒答升级

- **接线**：`knowledge_agent` 注入 `KnowledgeDeps`；`drug_agent` 接 `review_prescription_tool`。
- **分层检索**：Milvus collection 增加 `department`、`question_type` 字段，filter 升级为 `doc_type + department + question_type` 组合，支撑 #4 的分项定位（解析/切块/过滤/embedding）。
- **citation**：新增 `citations` 表（doc_id / chunk_index / page / score / confidence），SSE 增 citation 事件。
- **拒答升级**：`hallucination_check` fail-close；无证据 / 低置信 / 超权限 / 急症 / 下游故障 → `action ∈ {answer, refuse, escalate}`，绝不填充。
