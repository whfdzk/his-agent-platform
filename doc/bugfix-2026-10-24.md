# 后端代码审查与 Bug 修复记录

- 日期：2026-10-24
- 范围：`src/` 全量审查（core / infra / agents / knowledge / api / tools / modules）
- 原则：最小化修复，与邻近代码风格一致，不做无关重构

## 一、修复清单

### 1. 异常处理器签名错误（全局性，严重）

**文件**：`src/core/exceptions.py`

**问题**：Starlette 约定异常处理器必须接收 `(request, exc)` 两个参数，原实现只声明了 `exc` 一个参数。导致 `BizException` 抛出后处理器自身抛 `TypeError`，最终所有业务异常都以原始 500 返回，业务错误码体系完全失效。

**修复**：`biz_exception_handler` / `global_exception_handler` 增加 `request: Request` 参数。

**验证**：TestClient 请求抛 `BizException(40001)` 的路由，返回 `200 {"code": 40001, "message": ..., "data": null}`。

### 2. 向量化模型用错类（知识库导入/RAG 必崩，严重）

**文件**：`src/api/routers/knowledge.py`、`src/agents/inquiry/graph.py`

**问题**：使用 `from llama_cloud import OpenAiEmbedding` 构造 embedding 模型。该类是 llama_cloud 的**配置元数据模型**（pydantic v1），根本不具备 `aembed_documents` / `aembed_query` 能力。文档上传导入、问诊症状 Milvus 语义兜底匹配一执行即 `AttributeError`。

**修复**：统一替换为 `langchain_openai.OpenAIEmbeddings`（SiliconFlow Qwen3 Embedding），并显式传 `check_embedding_ctx_length=False`，与 `supervisor_agent._get_embedding_model()` 保持一致。

### 3. 错误的模块导入路径（启动/运行时崩溃）

以 `infra.*` / `tools.*` / `agents.*` 顶层包导入（仅当 `src` 在 `sys.path` 时才可能生效），与 `src.main:app` 的标准启动方式不符：

| 文件 | 原导入 | 修复后 |
|---|---|---|
| `src/api/routers/knowledge.py` | `from infra.rustfs_client import upload_file` | `from src.infra.rustfs_client import ...` |
| `src/agents/supervisor_agent.py` | `from tools.worker_tools import ...` | `from src.tools.worker_tools import ...` |
| `src/tools/worker_tools.py` | `from agents.inquiry.graph import ...` | `from src.agents.inquiry.graph import ...` |
| `src/agents/workers/inquiry_agent.py` | `from agents.inquiry.state import ...` | `from src.agents.inquiry.state import ...` |
| `src/knowledge/doc_ingestion.py` | `from src.knowledge.mineru_client import parse_document` | `from src.infra.mineru_client import ...`（文件实际在 infra 下） |
| `test/test_inquiry_agent.py` | `from agents.workers.inquiry_agent import ...` | `from src.agents.workers.inquiry_agent import ...` |
| `test/test_supervisor_agent.py` | `from agents.supervisor_agent import ...` | `from src.agents.supervisor_agent import ...` |

其中 `doc_ingestion.py` 的错误路径被 try/except 吞掉，导致 **MinerU 高精度解析永远静默失效**、每次都回退 LlamaIndex。

### 4. MinerU 配置项缺失（AttributeError）

**文件**：`src/core/config.py`

**问题**：`src/infra/mineru_client.py` 引用 `settings.MINERU_API_URL / MINERU_BACKEND / MINERU_TIMEOUT`，但 `Settings` 未定义这三个字段，访问即抛 `AttributeError`（同样被 try/except 吞掉）。

**修复**：在 Settings 中补充默认值 `http://localhost:8888` / `pipeline` / `120`，可通过 `.env` 覆盖。

### 5. NL2SQL `NameError`（功能必崩）

**文件**：`src/knowledge/nl2sql.py`

**问题**：`search_sql()` 中使用了 `validated`，但它是 `search_sql_raw()` 的局部变量——`search_sql` 一调用必抛 `NameError`。此外 `search_sql_raw` 返回类型混乱（失败返回 str，成功返回 list）。

**修复**：`search_sql_raw` 统一返回 `(data, executed_sql)` 元组；`search_sql` 使用返回的 SQL 拼装回答 Prompt。

### 6. 健康检查 Redis 永远报错

**文件**：`src/main.py`

**问题**：`redis_client = await get_redis_client()`——`get_redis_client` 是同步函数，`await` 非 awaitable 直接 `TypeError`，`/health/deps` 的 redis 检查永远显示 degraded。

**修复**：去掉 `await`。

### 7. 问诊结束挂号文案显示元组（多轮问诊路径）

**文件**：`src/api/routers/chat.py`（审查时该文件已被并行更新，此问题在最新版本中已由作者修复为元组解包，确认无需再改）

**说明**：`handle_handoff` 返回 `(文案, 结构化预约数据)` 元组，早期版本 `f"{reply}\n\n---\n{handoff_reply}"` 会把元组整体渲染给用户。

### 8. 非数字 user_id 导致问诊首轮 500

**文件**：`src/agents/inquiry/graph.py`

**问题**：`run_inquiry` 首轮将字符串 `user_id` 直接塞进 `PatientContext.patient_id`（`int | None`）。前端传非数字 ID 时 pydantic 校验抛 `ValidationError`，整个问诊流程 500。

**修复**：首轮初始化时 `int(user_id)` 失败则置 `None`（与 `node_load_context`、`handle_handoff` 的容错策略一致）。

### 9. 长期记忆 key 冲突覆盖

**文件**：`src/tools/store_tools.py`

**问题**：`save_memory` 用 `memory_{秒级时间戳}` 作 key，同一秒内保存多条记忆会被 MilvusStore 的 upsert 语义覆盖，造成记忆丢失。

**修复**：key 追加 8 位 uuid 后缀。

### 10. 文档列表未按 doc_id 去重 / 文件名路径穿越

**文件**：`src/api/routers/knowledge.py`

- `list_documents` 注释声称"按 doc_id 去重"但实际未去重 → 补充去重逻辑。
- `upload_document` 直接用 `file.filename` 拼 MinIO 对象键，`../` 可路径穿越且 `filename` 可能为 `None` → 先 `os.path.basename()` 归一化并做空值守卫，后续 `doc_name` 一并使用清洗后的文件名。
- `list_notifications` 参数注解 `category: str = None` → `str | None = None`。

## 三、已知限制（未修改，仅记录）

1. `MilvusStore` 的 `batch()` 用 `asyncio.run()` 桥接同步接口，LangGraph 线程池场景可用，但与异步事件循环并存时有理论上的事件循环开销，属上游设计取舍。
2. `session.py` 会话列表依赖 Redis TTL（1 小时），历史会话仅能从 consultations 补全，代码注释已声明。
3. `model_config.py` 的模型配置需重启后端才生效（接口返回值中已提示），后续可接入运行时热加载。
4. `knowledge.py` 的 `_get_deps()` 每次请求新建 `MilvusClient`，功能正确但可优化为模块级复用。
