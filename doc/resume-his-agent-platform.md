# 医疗智能体平台（HIS Agent Platform）

> **角色**：核心开发 / 后端与 Agent 架构负责人
> **周期**：2026.xx – 至今（按实际填写）
> **规模**：后端 2.1 万行 Python（141 模块）· 前端 1.2 万行 TS/TSX（3 包 25 页）· 38 张表 · 24 个 API 路由

---

## 一、项目背景

医院与区域医疗场景的 AI 服务入口。真实就医链路被拆散在多个系统里：患者先要判断"挂哪个科"，再描述症状、上传报告、核对用药，运营方还需要统计就诊量与科室排名。同类产品大多停在单轮问答或固定表单，缺少**可控的多轮问诊、证据溯源、急症兜底与生产级稳定性**，无法进入真实业务。

本项目把上述环节收敛为一个对话入口：一个 Supervisor 统一路由，下辖 7 个专项 Agent，配套患者端与运营管理端双站点，并按可上线标准完成鉴权、限流、幂等、断线续传、安全审核与全链路可观测。

## 二、核心功能

| 能力 | 说明 |
| --- | --- |
| **智慧问诊** | 自研 9 节点 LangGraph 状态机：加载患者上下文 → 急症前置拦截 → 症状抽取 → 澄清/图谱查询 → 症状追问 → 结论 → 落库，最终输出科室建议与挂号动作 |
| **报告解读** | 检验/影像报告上传后三级解析兜底（MinerU → 视觉模型 → 文本抽取），指标抽取含别名、单位与参考区间，落库后支持趋势对比、重新解析与删除 |
| **药物服务** | 说明书检索、剂量核对、药物相互作用（知识图谱）、过敏风险提示与用药记录 |
| **慢病管理** | 血压/血糖/体重等指标记录、趋势图、健康计划与提醒 |
| **就医导引** | 科室介绍、按症状推荐科室、就诊资料准备、挂号预约 |
| **医学知识问答** | 文档 / 知识图谱 / NL2SQL / 融合四通道检索，rerank 精排 + 幻觉检测，回答可溯源到文档与页码 |
| **运营数据** | 自然语言转 SQL 查询就诊量、科室排名、收入统计，带只读白名单与 PHI 拦截 |
| **平台侧** | 患者端 12 页（对话、历史回放、预约日历、报告对比、健康档案）；管理端 13 页（Dashboard、用户、Agent、Prompt 版本、模型与故障转移、知识库、会话、安全审计、调用轨迹、Token 用量、会员、系统配置） |

## 三、整体架构与技术选型

```
患者端 / 管理端（React + TS，pnpm workspace 复用 shared）
        │  REST + SSE（心跳 / seq 续传 / 幂等键）
        ▼
FastAPI（纯 ASGI 中间件链：request_id → 日志 → 限流 → 路由）
        ├── Supervisor Agent（ReAct 意图路由，规则前置 + LLM 兜底）
        │     └── 7 个 Worker Agent（问诊状态机 / 报告 / 药物 / 健康 / 导引 / 知识 / 运营）
        ├── 知识层：Milvus（文档+长期记忆）· Neo4j（图谱 NL2Cypher）· Rerank · NL2SQL
        ├── 治理层：SafetyEngine（输入/输出双向审核）· Trace/Span · PHI 脱敏 · 审计
        └── 数据层：PostgreSQL（38 表 / 13 迁移）· Redis（checkpoint/缓存/限流）· RustFS
```

| 分层 | 选型 | 关键理由 |
| --- | --- | --- |
| 运行时 / Web | Python 3.13 · FastAPI · Uvicorn（uvloop + httptools） | 全异步，SSE 长连接不占线程 |
| Agent 编排 | LangChain 1.2 + LangGraph 1.1 | 灵活路由用 ReAct，强流程用 StateGraph |
| 会话记忆 | AsyncRedisSaver（短期）+ 自研 MilvusStore（长期） | 跨进程共享，多副本无需 sticky session |
| 数据 | SQLAlchemy 2.0 async + asyncpg + Alembic | 短作用域会话 + 版本化迁移 |
| 检索 | Milvus（COSINE/IVF_FLAT，1024 维）+ Neo4j 5.28 + dashscope Rerank | 语义、结构化、关系三类证据互补 |
| 缓存 / 队列 | Redis（业务缓存、会话锁、限流计数、批量落库） | 单点复用，降低外部依赖数量 |
| 对象存储 | RustFS（S3 兼容） | 报告与知识原文与向量库解耦 |
| 可观测 | loguru（JSON + request_id）· Prometheus · Sentry（上报前剥离 PHI） | 事故可定位、指标可告警 |
| 前端 | TypeScript 5.6 · React 18 · Vite 5 · Tailwind · pnpm workspace | 三包复用类型、API Client 与 SSE 解析 |
| 部署 | 多阶段 Dockerfile（非 root）· Compose 双副本 · Nginx | SSE 专用调优 + 双层限流 |

## 四、个人职责

- **架构设计**：划分 `api / agents / knowledge / modules / infra / core` 六层，确立"core 不反向依赖 modules 与 infra"的分层约束，并用一条分层测试固化，避免基础设施细节渗透进业务内核。
- **Agent 编排**：设计 Supervisor + Worker 双层结构，实现意图路由、工具白名单、子 Agent 可配置化调度，以及问诊域的确定性状态机。
- **知识检索**：搭建文档入库（解析 → 分块 → 向量化 → 索引）、四通道并行检索、rerank 精排与幻觉检测链路。
- **生产化改造**：主导 SSE 语义重构、JWT 鉴权收口、消息幂等、会话互斥、多级限流、并发闸门、执行预算、批量落库与断线续传。
- **安全合规**：实现输入/输出双向安全审核、急症阻断、PHI 脱敏（手机号/身份证/正文扫描）与审计落库。
- **可观测**：设计 trace/span 模型覆盖 API → Agent → Tool → LLM → Retrieval → Safety，落地采样、Token 统计与 Prometheus 指标。
- **前端协同**：负责 shared 包（类型、API Client、SSE 解析）与双站点页面，管理端从 4 页扩展到 13 页。
- **工程规范**：13 条 Alembic 迁移串联单一 head、268 个确定性单测默认不依赖外部服务、Docker + Nginx 一键部署。

## 五、关键实现与设计亮点

**1. 双模编排：灵活路由 + 确定性流程并存**
纯 ReAct 编排在医疗场景不可控——追问轮次不可枚举、结论不可复现。做法是把"意图分发"交给 Supervisor（低温度 0.1，规则前置 + LLM 兜底），把"问诊流程"固化为 9 节点 StateGraph：节点只做单件事，路由由函数式条件边决定，`deps` 通过闭包注入，图按请求编译（放弃跨请求缓存，避免 db_session 与会话状态串扰）。收益：问诊路径可枚举、单节点可单测、异常有明确落点。

**2. 症状槽位 + 置信度加权，让问诊"会收敛"**
状态机维护四类症状集合（已确认 / 已否认 / 图谱外 / 已问过），候选疾病按"命中症状占比"给基础置信度，再叠加上下文权重：既往病史 +0.15、长期记忆 +0.10、**核心症状**（仅属于该疾病的独有症状）被否认 −0.20。收敛采用双阈值：Top1 ≥ 0.70 或 Top1 领先 Top2 ≥ 0.30，否则继续追问；10 轮强制出结论并标注"信息不足"。收益：既避免"问两句就下诊断"，也避免无限追问，同时把"为什么是这个科室"变成可解释的分数。

**3. 四通道混合检索，回答有据可查**
文档（Milvus）、图谱（实体抽取 → NL2Cypher → 执行，失败带错误提示重试 2 次）、运营数据（NL2SQL）、融合四路并行，`asyncio.gather(return_exceptions=True)` 保证单通道故障不拖垮整体；结果统一格式化后交给融合 Prompt，再经 rerank 精排与幻觉检测，输出附来源文档与页码。配套的 SQL 护栏值得单列：只允许 SELECT、屏蔽写操作关键字、`patients` 表与 `phone/id_card` 或通配符共现即拦截（先剔除 `count(*)` 再判 `*`）、无 LIMIT 自动补 100、执行带超时——把"模型生成 SQL"这个高危动作关进笼子。

**4. 生产级 SSE：把"流式"当协议设计，而不是当接口实现**
首字节立即 ping、每 15s 心跳帧，解决 LLM 首 token 可能 60s+ 导致的网关超时；循环内检测 `is_disconnected()`，客户端断开即取消 LLM 任务，不再空跑整条链路；整轮 150s 硬超时（问诊一轮含 3–6 次串行 LLM 调用，90s 会误杀正常问诊）。每个业务事件带 `id: seq`，重连后通过 `?after_seq=` 增量补齐；`client_message_id` + Redis SETNX 做 5 分钟幂等，重复提交直接重放上次回复、不重跑 LLM；同会话 `SET NX PX` 互斥锁消除并发消息交叉覆盖。错误统一为 `{code, message, retryable}`，堆栈只进日志。

**5. 并发与成本治理：让 10k 在线目标有落点**
按"单机 Compose + Nginx、2 副本、10k 在线（活跃对话 5–10%）"反推容量参数：LLM 全局信号量 200/进程（含**流式**版本，信号量从首 token 持有到末 token，此前逐 chunk 消费会绕过限流直接打爆上游）、SSE 连接闸门 4000/进程、PG 连接池 30+20 且 `pool_pre_ping`、httpx 连接池 400、Redis 双池 200。再叠三层限流：滑动窗口 30 msg/min（登录按用户、游客按 IP）、用户级并发槽、执行预算（12 次 Agent / 20 次工具 / 6 万 Token / 240s / 检索 8 条）。DB 会话从"SSE 全程持有"改为短作用域按需创建，长连接不再占满连接池。

**6. 消息持久化：批量队列 + PG 为唯一事实源**
早期每次 LLM 调用都新建 DB 会话写 Token 用量，10k 并发下直接打爆连接池。改为进程内队列 + 单 consumer 攒批（50 条或 500ms），批量 upsert 入 PG，失败退避重试且不阻塞主链路；消息落库依赖 `(session_id, client_message_id)` 唯一索引做二次幂等兜底，Redis 只作热缓存。顺带修掉 `asyncio.create_task` 无引用被 GC 导致的偶发丢数据。

**7. 医疗安全做在链路上，而不是写在免责声明里**
SafetyEngine 用确定性规则而非 LLM 判风险：输入侧识别急症与自伤信号，critical 命中直接返回急救指引并**阻断本轮**（不再让模型说"建议再观察"）；输出侧审核绝对化诊断、具体剂量、疗效保证，命中则追加免责或整段替换，并标记人工复核。每次审核写安全事件并挂到 trace 的 safety span 上。隐私侧：Sentry 上报前剥离 PHI，trace 只存结构化字段与脱敏摘要、绝不写病历原文，患者序列化输出经手机号/身份证脱敏。

**8. 配置化运行时 + 模型故障转移，改行为不用改代码**
Agent 的提示词、模型、温度、工具白名单、子 Agent 清单、会话压缩阈值全部落库，`published` 才生效、`draft/disabled` 回退代码内置默认；配置对象作为缓存指纹，保存即热更新，旧实例优雅下线。模型侧维护候选链（60s 缓存 + 管理端主动刷新），读库失败沿用上一条链，单模型故障自动切换——把"换模型"从一次发版降级为一次点选。

**9. 全链路追踪：让"这轮为什么答错"可复盘**
自研轻量 trace：一次请求聚合为一棵树（api / agent / tool / llm / retrieval / safety / final_response），记录 Agent 与 Prompt 版本、模型与版本、工具调用、检索来源、Token、耗时与错误类型；按 `TRACE_SAMPLE_RATE` 采样，未采样时链路照常跑、只是不留轨迹；落库同样走批量队列。检索记录只保留 doc_id 与 score，不保留正文。

## 六、相较同类方案的优势

| 维度 | 常见做法 | 本项目 |
| --- | --- | --- |
| 多轮问诊 | 单轮问答，或纯 ReAct 自由追问 | 槽位 + 加权置信度 + 双阈值收敛 + 轮次上限，路径可枚举、可单测 |
| 知识问答 | 单路向量检索，答错无从追溯 | 文档/图谱/NL2SQL 并行 + rerank + 幻觉检测 + 文档页码溯源 |
| 流式体验 | 裸 SSE，断线即丢消息 | 心跳保活 + seq 续传 + pending 补齐 + 幂等重放 + 退避重连 |
| 稳定性 | 无限流，上游一慢全站雪崩 | 信号量 + 连接闸门 + 三层限流 + 执行预算 + 降级开关 |
| 医疗合规 | 事后免责声明 | 输入阻断 + 输出审核 + PHI 脱敏 + 审计落库 + 急症分级 |
| 变更成本 | 改提示词/模型要发版重启 | Agent/Prompt/模型热更新 + 版本回滚 + 故障转移链 |
| 横向扩展 | 会话状态在进程内，必须 sticky session | 状态全在 Redis/PG，Nginx 普通轮询即可多副本 |

## 七、可量化成果

- 交付 **7 个专项 Agent**、**9 节点**问诊状态机、**4 通道**混合检索，覆盖问诊→挂号→报告→用药→健康→知识→运营全链路。
- 后端 **2.1 万行 / 141 模块**，前端 **1.2 万行 / 3 包 / 25 页**，**38 张表 / 13 条迁移 / 24 个路由模块**。
- **268 个**确定性单测（32 个测试文件）默认零外部依赖，可在任意机器回归；集成用例用 `-m integration` 隔离。
- 容量参数按 **10k 在线**目标落地：2 副本 × 4000 SSE 连接/进程、LLM 200 并发/进程、PG 池 30+20。
- 首 token 等待期以 15s 心跳兜住 60s+ 网关超时；单轮 150s 硬超时；SSE 断连即取消任务，避免无效 LLM 计费。
- 幂等窗口 5 分钟，重复提交 **零 LLM 重跑**；落库 50 条/500ms 攒批，Token 写入不再随并发线性增长。
- 管理端从 4 页扩展到 **13 页**，运营侧无需研发介入即可调 Prompt、换模型、管知识库、查轨迹与审计。
